## 3. إدارة قاعدة البيانات (D1 Migrations)

### تطبيق الهيكل البرمجي (Schema)
- **محلياً**:
  ```bash
  npx wrangler d1 execute khotba-db --local --file=schema.sql
  ```
- **على الإنتاج**:
  ```bash
  npx wrangler d1 execute khotba-db --remote --file=schema.sql --yes
  ```

### ترحيل بيانات جديدة من Google Sheets
لو حدث أي تعديل في الشيت وتريد إعادة الترحيل:
1. افتح محرر Apps Script في الشيت وشغّل دالة `exportAllJson()` من ملف `apps-script/Export.gs`.
2. نزّل ملف الـ JSON الناتج وضعه في المجلد الرئيسي باسم `snapshot.json`.
3. شغّل سكريبت التحويل الآلي:
   ```bash
   node scripts/migrate-json-to-sql.js snapshot.json migration.sql
   ```
   (هذا السكريبت يطبّق تلقائياً دالة تطبيع أرقام الهواتف، ويعيد الصفر البادئ المفقود، ويرحّل الجلسات النشطة حتى لا يُطرد المستخدمون).
4. طبّق الملف على D1:
   ```bash
   npx wrangler d1 execute khotba-db --remote --file=migration.sql --yes
   ```

## 4. كيفية تشغيل الاختبارات والتحقق

يحتوي المشروع على طاقم اختبارات تكاملي شامل يفحص كل العمليات الـ 21:

1. **اختبار خوارزمية التشفير (Hash Parity)**:
   ```bash
   node scratch/test_hash.js
   ```
   يختبر مطابقة SHA-256 المتزامنة للـ SubtleCrypto والـ Node Crypto على الحروف العربية وحدود البايتات (55، 56، 63، 64، 65).

2. **الاختبار التكاملي الشامل (E2E Integration Test)**:
   ```bash
   node scratch/test_e2e.js
   ```
   يختبر 29 حالة فحص دقيقة:
   - فحص الصحة والإصدار.
   - الدخول بالباسورد، والرفض بالباسورد الخطأ، والجلسات منتهية الصلاحية.
   - عمليات المساجد والخطباء والتفضيلات.
   - توليد الجمعة وحجز الخطباء الثابتين.
   - منع الحجز المزدوج بنيوياً في الطلب ومع المساجد الأخرى (`KHATIB_DOUBLE_BOOKED`).
   - منع التعارض التزامني (`STALE_WRITE`).
   - الحسابات الرقمية لأحمال الخطباء (`getLoadCounts`).
   - الجدول العام للمواطنين بدون تسجيل دخول داخل نطاق النشر المتاح.

3. **التحقق من السيرفر الحي**:
   ```bash
   node scratch/test_remote_prod.js
   ```

## 5. ما الذي تغير في السلوك مقارنة بـ Apps Script؟

| الجانب | سابقاً (Apps Script + Sheets) | حالياً (Cloudflare Workers + D1) |
|---|---|---|
| **العقد مع الواجهة** | - | **لم يتغير بحرف واحد** (نفس أسماء العمليات الـ 21، نفس شكل الـ JSON، نفس أكواد ورسائل الأخطاء). |
| **سرعة الاستجابة** | 1.8 - 3.5 ثانية لكل طلب | **20 - 90 مللي ثانية** على شبكة إيدج العالمية. |
| **أرقام الهواتف** | كان الشيت يحذف الصفر البادئ (`1001234567`) | **TEXT** صارم ومطبع يحافظ على الصفر دائماً (`01001234567`). |
| **التواريخ** | كانت كائنات Date في الشيت وتتعرض لخطأ اليوم الواحد | **TEXT** بصيغة `yyyy-MM-dd` مطابقة ومستقرة. |
| **القيم المنطقية** | خليط بين 'TRUE' و booleans | **INTEGER 0/1** صارم على مستوى قاعدة البيانات. |
| **الحجز المزدوج** | فحص برمجي فقط كان يفشل أحياناً عند التزامن | **فهرس فريد على مستوى المحرك** (`UNIQUE(date, khatib_id)`) يستحيل تجاوزه. |
| **التشفير والـ CPU** | نداءات بطيئة في Google | خوارزمية SHA-256 متزامنة يدوية تستهلك **أقل من 0.1ms** من حد الـ 10ms CPU. |
| **التشخيص وفحص الصحة** | لا يوجد مسار صحة مخصص | إضافة مسار `GET /health` للتحقق الفوري من حالة السيرفر والداتابيز بدون توكن. |
| **الرجوع الاحتياطي** | - | **شيت Google والـ Apps Script القديم محفوظان بالكامل ولم يمسّا** ويمكن الرجوع إليهما في أي لحظة عبر تغيير سطر واحد في `config.js`. |
