# التوفر الشهري المتكرر للخطباء — التوثيق المعماري وميثاق التكامل (Phase C Foundation)

## 1. نظرة عامة
توفر هذه المرحلة الأساس البرمجي والبياني المستقل لنمط **التوفر الشهري المتكرر** (Recurring Monthly Availability) لخطباء الجمعة في تطبيقي **أوقاف 15 مايو** و**أوقاف التبين**.
القاعدة استرشادية بحتة (Advisory)؛ لا تفرض منعاً قسرياً على الجدولة، ولا تسجل حضوراً صريحاً أو جاهزية أسبوعية (تلك تظل خاضعة لبوابة الخطباء وجدول `khatib_readiness`).

---

## 2. ميثاق التقويم الإقليمي (Calendar Policy)
- **منطقة 15 مايو (`REGION_ID = '15may'`)**:
  - الحساب **ميلادي بالكامل** (Gregorian).
  - ترتيب الجمعة (1 إلى 5) يُحسب بناءً على يوم الجمعة داخل الشهر الميلادي المدني.
- **منطقة التبين (`REGION_ID = 'tebeen'`)**:
  - الحساب **هجري حصراً** باعتماد تقويم **أم القرى** (`islamic-umalqura`).
  - المنطقة الزمنية المعتمدة هي توقيت القاهرة (`Africa/Cairo`).
  - ترتيب الجمعة (1 إلى 5) يُحسب بناءً على يوم الجمعة داخل الشهر الهجري لأم القرى.
  - ترفض الدوال بصراحة أي بيئة تشغيل لا تدعم تقويم `islamic-umalqura`، ولا تلجأ أبداً لتقويم مختلف بصمت.
- **التواريخ المدنية المخزنة**:
  - تحتفظ جميع التكليفات والجمعات بصيغتها المدنية القياسية ISO 8601 (`YYYY-MM-DD`). لا تحويل ولا تخزين لتواريخ هجرية بديلة في الجداول، ولا تحليل قسري للملاحظات النصية التاريخية.

## 4. ميثاق واجهة البرمجة (API Contract)

### هيكل كائن التوفر في الاستجابة (`publicKhatib_`):
```json
{
  "id": "K1",
  "name": "الشيخ أحمد",
  "phone": "01012345678",
  "type": "primary",
  "notes": "",
  "active": true,
  "preferences": ["M1"],
  "availability": {
    "mode": "all",
    "weeks": [1, 2, 3, 4, 5]
  }
}
```
أو للنمط المخصص:
```json
{
  "availability": {
    "mode": "custom",
    "weeks": [1, 3]
  }
}
```

### قواعد التحقق الصارم والتحديث (Validation Rules):
1. **الإنشاء (`createKhatib`)**:
   - عند إغفال التوفر (`undefined`): الافتراضي هو `{ mode: 'all', weeks: [1, 2, 3, 4, 5] }`.
   - عند تمرير قيمة صريحة فارغة (`null`): يُرفض الطلب فوراً بكود `BAD_REQUEST`.
2. **التعديل (`updateKhatib`)**:
   - عند إغفال التوفر (`undefined` من عملاء قدامى): تُحفظ القاعدة المخزنة في قاعدة البيانات دون أي تعديل.
   - عند تمرير قيمة صريحة فارغة (`null`): يُرفض الطلب بكود `BAD_REQUEST` وتظل السجلات المخزنة محفوظة بالكامل.
   - عند تحديث القاعدة: يجب أن يكون `mode` إما `'all'` أو `'custom'`.
3. **التحقق من الجمع (`weeks`)**:
   - في النمط المخصص (`custom`): يجب أن تكون `weeks` مصفوفة غير فارغة تحتوي على أرقام صحيحة فريدة بين `1` و `5`، وتُرفض القيم المكررة أو الخارجة عن النطاق.
   - في نمط الكل (`all`): إذا تم تمرير مصفوفة جمع، يُشترط أن تكون أرقامها صالحة [1..5] ويُرفض أي تشويه فيها.
4. **البيانات التالفة في قاعدة البيانات**:
   - إذا وُجد سجل مخصص تالف في قاعدة البيانات (مثل JSON غير صالح أو جمع خارج النطاق)، يُعاد كـ `{ mode: 'invalid', weeks: [], error: '...' }` وتعتبره دالة الفحص `isKhatibAvailable` **غير متاح** فوراً، ولا تعلن عن توفره الافتراضي كما كان يحدث سابقاً.

## 5. المكتبة المشتركة وتفادي التكرار (Shared Helpers)

### ملفات المكتبة:
- **`assets/availability.js`**: المصدر الوحيد لتنفيذ المنطق المشترك، مصمم بصيغة UMD بدون أي مكتبات خارجية:
  - في المتصفح: يُسجل النطاق العام `window.KhatibAvailability` دون تلويث النطاق الجذري.
  - في بيئة Node.js / CommonJS: يُصدر عبر `module.exports`.
- **`worker/src/availability.js`**: مغلف استيراد وإعادة تصدير ES Module خفيف (20 سطراً فقط) يستورد من `assets/availability.js` لضمان عدم تكرار أي أسطر كود بين المتصفح والسيرفر.

### الدوال المصدرة الرئيسية:
- `parseCivilDate(isoDate)`: تحليل وتدقيق التاريخ المدني ورفض المستحيلات.
- `assertFriday(isoDate)`: التحقق من أن التاريخ يوافق يوم جمعة.
- `resolveCalendar(regionOrCalendar)`: تعيين التقويم المناسب للمنطقة.
- `getCalendarDateParts(isoDate, regionOrCalendar)`: استخراج تفاصيل اليوم والشهر والسنة الميلادية أو الهجرية (أم القرى).
- `getFridayOrdinal(isoDate, regionOrCalendar)`: حساب ترتيب الجمعة الفعلي داخل الشهر (1 إلى 5).
- `validateAvailability(raw)`: تدقيق صحة كائن التوفر.
- `normalizeAvailability(raw)`: تطبيع كائن التوفر وإعادته مرتباً.
- `parseStoredAvailability(k)`: تدقيق البيانات المخزنة من قاعدة البيانات واستخراج الحالة بما فيها كشف الحالات التالفة.
- `formatAvailabilityRule(availability, options)`: صياغة نص عربي واضح للقاعدة (مثل: "كل جمعة" أو "الجمعة الأولى والثالثة من كل شهر").
- `isKhatibAvailable(availabilityOrKhatib, isoDate, regionOrCalendar)`: فحص مطابقة الخطيب لتاريخ جمعة محدد.

## 6. واجهة المستخدم (`khatibs.html`)
- إضافة أدوات اختيار التوفر الشهري في نموذج إضافة/تعديل الخطيب:
  - خياران عبر أزرار راديو: "كل جمعة (الافتراضي)" و "جمع محددة من كل شهر".
  - مربعات اختيار متعددة للجمع (الأولى، الثانية، الثالثة، الرابعة، الخامسة) مع فحص عدم تركها فارغة.
  - مؤشر نصي يوضح نص القاعدة لحظياً باستخدام `KhatibAvailability.formatAvailabilityRule`.
  - نص إرشادي موجز وواضح يوضح أساس التقويم:
    > "ℹ️ أساس التقويم: التبين هجري (أم القرى) — 15 مايو ميلادي. القاعدة استرشادية للتوزيع الشهري ولا تُسجل جاهزية أو تأكيد حضور، ولا ترتبط بالملاحظات النصية القديمة."
- في جدول الخطباء: إظهار شارة مميزة بجانب اسم الخطيب إذا كان له توفر مخصص (مثل: `🗓️ الأولى والثالثة`) أو شارة تنبيه إذا كانت القاعدة تالفة.
